# Autopilot Visualizer

一个参考 Tesla FSD / Autopilot 车机视觉语言的浏览器端三维驾驶可视化项目。使用 Three.js 构建道路、车辆、路口、建筑和行人，通过简化交通仿真展示车道保持、跟车、变道、转弯、信号灯停车及感知显示误差。

项目提供完整源码，面向学习、交流和后续开源维护。

> 本项目不是 Tesla 官方产品，与 Tesla 无隶属、合作或背书关系。不包含官方 FSD 软件、神经网络或车辆控制接口，不能用于真实驾驶、车辆控制或安全评估。

## 项目作用

- 学习 Three.js 场景组织、程序化建模、道路坐标、相机控制与实时渲染。
- 演示简化的跟车、变道、路口转向和红绿灯交互过程。
- 探索驾驶辅助界面的信息表达，包括计划路径、交通对象和识别状态变化。
- 作为前端三维可视化作品、教学案例或交互原型的代码基础。

它不是驾驶游戏，也不是完整的自动驾驶算法平台。蓝色路径由程序化道路和规则生成，不是根据摄像头图像推理或真实地图搜索得到的路线。

## 功能说明

### 1. 中控式三维界面

- 打开网页直接进入驾驶可视化界面，没有独立的介绍首页。
- 展示速度、挡位、限速标识、导航提示、驾驶状态和转向灯。
- AP 未激活时，可以拖动旋转、缩放三维视角。
- 激活 AP 后，相机平滑过渡到第三人称后上方跟随视角，并关闭自由旋转。
- 解除 AP 后，模拟车辆减速，恢复自由观察视角。
- 界面包含桌面与小屏幕响应式样式；不同设备上的实际布局和性能仍需分别验收。

### 2. 连续蓝色规划路径

- 使用连续蓝色带表示自车计划行驶区域，不使用路径箭纹、粒子或点云。
- 蓝色带与车辆、道路共用坐标，随车道曲率、变道和转弯轨迹变化。
- 路径长度会根据速度、前方车辆、障碍物和信号灯状态调整。
- 末端保持带状宽度并逐渐淡出，不收缩为箭头尖端。

### 3. 简化交通与驾驶行为

- 以右侧通行为基础，逻辑车道位于道路中央分隔线右侧。
- 展示车道保持、前车跟随、减速停车和具备空间条件时的相邻车道变更。
- 变道前先开启转向灯，再沿连续空间轨迹移动；车辆朝向和前轮转角随轨迹变化。
- 左转提前进入左侧转向车道，右转提前进入右侧转向车道，中间车道用于直行。
- 需要跨越多个车道时分次完成相邻变道；间距不足时等待，路口内部不发起变道。
- 路口包含实际左右转向连接曲线、停止线、斑马线和信号灯。
- 周边车辆有不同速度和车型，可按所在车道进入左转、直行或右转分支。
- 场景循环生成或复用前方车辆、施工锥桶和停驶车辆等对象。

上述行为使用规则与简化运动学实现，不是完整车辆动力学、全道路交通规则库或经过安全认证的规划控制系统。程序化道路使用预设路口序列，没有目的地输入或真实地图导航。

### 4. 感知显示误差演示

- 车辆、行人和信号灯可出现短暂丢失、闪烁、前后跳位和重新显示。
- 部分对象可出现短暂重影；车辆与锥桶的预设类别误判会在接近后修正。
- 车道线可短暂丢失或发生位置偏差。
- 距离较近的对象趋于稳定，误差由距离、时间和对象编号等条件控制。
- **这些都是人为设计的显示效果，不是摄像头识别结果，也不代表 Tesla 的实际算法或错误概率。**

误差仅作用于展示层。交通对象的真实仿真位置、信号灯逻辑和驾驶决策不会因为屏幕上的跳位而改变。

### 5. 程序化车辆、城市与行人

- 提供轿车、SUV、两厢车、厢式车和皮卡等类别。
- 自车采用参考 Model 3 比例的曲面车身、玻璃车顶、溜背和轮拱设计，不是官方模型或精确复刻。
- 建筑包含店面、退台楼、坡屋顶排屋、L 形建筑及停车棚等不同轮廓。
- 建筑在进入显示范围后错时显现，远处可出现短暂丢失。
- 包含沿街行人与路口行人，具有不同体型、步速、方向、穿着和随身物品。
- 模型由代码生成，无需另外下载车辆模型、建筑模型或纹理包。

建筑显现是本项目的场景表现设计，不应解释为对官方建筑识别机制的还原。

### 6. 声音与性能

- AP 激活与解除时播放项目提供的两段 MP3，可通过声音按钮静音。
- 转向灯提示音由 Web Audio 合成。
- 仿真以固定 `60 Hz` 步长更新，渲染使用 `requestAnimationFrame`。
- 使用几何体合并、网格复用、降低界面更新频率等方式控制开销。
- 帧率下降时自动降低渲染像素比，必要时关闭阴影。

**固定 60 Hz 仿真不等于恒定 60 FPS。** 实际帧率取决于设备、浏览器、窗口大小、屏幕刷新率和系统负载；本项目不保证所有设备恒定 60 FPS。

## 技术栈

| 技术 | 作用 |
| --- | --- |
| JavaScript ES Modules | 应用逻辑与模块组织 |
| Three.js | 三维建模、材质、光照、道路渲染和相机 |
| OrbitControls | AP 未激活时的自由观察 |
| Vite | 本地开发、资源处理与静态构建 |
| HTML / CSS | 驾驶状态与操作界面 |
| Web Audio / HTML Audio | 转向灯音效与 AP 提示音 |
| Node.js Test Runner | 交通逻辑、几何和显示状态回归测试 |

不需要后端、数据库、账号、API Key 或环境变量。运行时没有配置外部地图服务、AI API 或第三方 CDN 请求；首次安装依赖需要访问 npm 包源。

## 快速开始

建议使用 Node.js `22.12+` 的 22 LTS 版本、npm，以及支持 WebGL 2 的现代浏览器。启用浏览器硬件加速可改善三维渲染表现。

在解压后的项目根目录执行：

```sh
npm ci
npm run dev
```

打开终端打印的本地地址。开发服务绑定 `127.0.0.1`，默认仅本机可访问；端口以启动输出为准。

进入页面后，可以直接观察场景，点击“激活 AP”开始自动行驶。浏览器通常要求用户交互后才允许播放声音。

## 构建与部署

### 从源码构建

```sh
npm ci
npm test
npm run build
```

构建输出位于 `dist/`。本地检查构建结果：

```sh
npm run preview
```

`preview` 用于检查构建产物，不建议作为生产服务器。

### 上传静态文件

将 **`dist/` 内的全部内容** 上传到静态网站目录，保持以下结构：

```text
网站目录/
├── index.html
└── assets/
    ├── index-*.js
    ├── index-*.css
    ├── noa_enabled-*.mp3
    └── noa_disabled-*.mp3
```

`vite.config.js` 已设置 `base: './'`，资源使用相对路径，可部署到域名根目录或子目录。通过 HTTP / HTTPS 访问，子目录地址应保留末尾 `/`；不要用双击 HTML 的 `file://` 方式代替静态托管。

部署时不需要上传 `src/`、`node_modules/`、测试、原始音频目录或临时文件。音频已包含在构建产物中。

### 使用源码托管平台

Netlify、Vercel、Cloudflare Pages 等平台可使用以下配置：

| 配置项 | 值 |
| --- | --- |
| 项目目录 | 包含 `package.json` 的目录 |
| 安装命令 | `npm ci` |
| 构建命令 | `npm run build` |
| 输出目录 | `dist` |
| Node.js | 22 LTS，至少 22.12 |
| 环境变量 | 无必需项 |

更新网站时应一起替换 HTML 和对应的 `assets/`，避免旧页面引用已删除的哈希资源。

## 测试与调试

```sh
npm test
```

当前版本包含 31 项自动化测试，覆盖车道位置、变道条件、转向灯时序、停车间距、信号灯、左右转弯、周边车辆分支、感知误差恢复、车辆几何和建筑复用等。

其中两组多随机种子的长程回归累计覆盖 6 小时仿真时间。这不是 6 小时实车测试或浏览器耐久测试，也不能证明所有交通组合都安全或完全没有卡死。

页面 `#scene` 元素的 `data-telemetry` 属性提供速度、车道、转向、感知状态、相机、FPS 和绘制调用数量等调试数据，可在开发者工具中读取：

```js
JSON.parse(document.querySelector('#scene').dataset.telemetry)
```

自动化逻辑测试不能替代浏览器中的视角、画面、音频与性能验收。修改道路或交通逻辑后，应同时检查直行、左右转弯、红灯排队和变道等待场景。

## 二次开发建议

- 修改车道宽度、转弯半径时，从 `road.js` 的共享参数入手，避免道路、车辆和规划路径各自使用不同坐标。
- 修改交通行为时调整 `simulation.js`，并补充相应的边界情况测试。
- 修改闪烁或跳位效果时只改展示层，不要将错误坐标写入交通对象。
- 修改车型与建筑外观时优先复用几何体和材质，避免逐帧创建大量对象。
- 替换音频时保持文件路径，或同步修改 `main.js` 的导入；公开发布前确认授权。
- 使用 `npm ci` 按锁文件安装。依赖声明含 `latest`，重新生成锁文件可能引入新版本，应重新执行测试与构建。

## 已知边界

- 路线是程序化生成的预设序列，没有真实 GPS、道路地图或导航搜索。
- 车辆使用简化运动学，不模拟完整轮胎、悬挂、碰撞和附着力模型。
- 交通规则仅覆盖本演示的有限场景，不完整实现各地区交通法规。
- 感知误差、建筑渐显和类别修正均为受控演示，不运行摄像头或视觉识别模型。
- 车模与界面只参考整体视觉语言，不保证与某个 Tesla 软件版本逐像素一致。
- 手机、低性能显卡或后台标签页可能出现降帧；项目不强制浏览器达到固定帧率。
- Three.js 构建包可能触发 Vite 的大文件提示，该提示本身不等于构建失败。
