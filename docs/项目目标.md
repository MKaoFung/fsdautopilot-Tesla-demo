# FSD 风格智能驾驶可视化演示网页：项目目标

## 最新修订：以本节为准

以下是用户后续反馈确定的新约束，优先于下方保留的初版规划：

- 白灰色 FSD 感知世界；自车重点参考 Model 3 的低车头、连续曲面、弧形玻璃顶和溜背比例，不使用积木式车厢。
- 彻底取消点云、颗粒、扫描线、蓝色路径箭纹及尖头。蓝色路径为有宽度的连续矩形色带，末端沿行进方向逐渐透明，停车时按停止线收短。
- 摄像头识别误差仅在显示层模拟：抖动、短暂消失、闪烁、位置跳变、重复轮廓与类别纠正；真实碰撞与决策坐标不跟着错误跳变。
- 街边建筑逐步、错时出现；行人包含不同体型、步速、方向和携带物，不局限于路口两个人。
- 必须有实际左右路口转弯，不以镜头旋转冒充。轨迹、车头、轮胎转角、转向灯、蓝色带和镜头方向需保持一致。
- AP 未激活时可自由旋转和缩放三维视角；激活后平滑过渡到固定跟随视角，解除后恢复旋转。
- 绿灯占更长时间，仍有黄灯、红灯停车和绿灯起步。
- 以 60 FPS 为性能目标，使用动态分辨率和受控绘制开销；实际帧率必须实测，不保证所有硬件和后台标签页强制维持 60 FPS。

后续开发提示词：继续完善现有 Three.js 页面，严格遵循上述约束。先复现问题再改代码；必须分别报告逻辑测试、构建、浏览器视觉与帧率验收的真实状态。不得把自建近似车型称为官方 Model 3 模型，不得把未经测量的 60 FPS 称为已达标。

## 1. 项目定位

制作一个打开即进入车辆中控屏的单页 3D 网页，呈现高级驾驶辅助系统的实时环境感知与路径规划过程。整体观感必须让熟悉 Tesla FSD 的用户一眼理解其参考来源：相近的空间构图、后上方视角、灰色简化车辆、蓝色规划路径、道路表达、对象配色与状态反馈节奏；但不使用 Tesla 商标，也不对原版界面进行逐像素复制。

页面不设置传统“场景选择”入口。用户看到的是一个持续运行的驾驶世界，只需点击一次“激活 AP”，车辆便开始自主巡航、寻路、跟车、避障、转弯与变道。

## 2. 核心体验目标

1. 第一眼像真实车机，而不是游戏菜单、数据后台或营销落地页。
2. 激活前，车辆静止或低速待命，环境感知持续工作，规划路径保持低亮度预览。
3. 点击“激活 AP”后，蓝色规划路径由车头向远方流动点亮，车辆平顺起步。
4. 行驶过程中随机出现其他汽车、路障、锥桶和道路宽度变化，系统自行作出可理解的决策。
5. 自动变道前必须先开启对应方向的转向灯，确认相邻车道安全后再完成变道，结束后自动关闭。
6. 场景持续演化，无需用户选择关卡或反复点击按钮。
7. 桌面端重点呈现 16:9 中控屏体验，同时兼容平板和手机横屏。

## 3. 视觉方向

### 3.1 画面构成

- 全屏深灰色车机背景，中心为无边框 3D 驾驶视野。
- 镜头位于车辆后上方，以略俯视的第三人称角度观察道路。
- 自车采用 FSD 可视化中类似的中性灰色简化 3D 车体：轮廓准确、体块干净、材质统一，不追求车灯内构、内饰、缝隙等写实细节，也不显示品牌标识。
- 道路使用哑光深灰材质，车道线、路缘与路面接缝保持细腻但低对比。
- 规划路径使用饱和但不过曝的电光蓝，宽度与当前可行驶空间相关。
- 周围车辆使用白、灰、黑以及少量低饱和颜色，避免喧宾夺主。
- 左侧保留紧凑的速度、挡位和 AP 状态；导航提示以轻量浮层融入画面。

### 3.2 粒子使用原则

使用粒子，但仅作为信息表达，不作为装饰性背景：

- 蓝色路径内部使用少量流动粒子，表达规划方向和系统已接管。
- 激活 AP 时产生一次由近及远的扫描脉冲。
- 传感器确认障碍物时，可短暂出现低密度轮廓点或扫描点。
- 粒子运动稳定、方向一致、数量受控，不使用漫天星点、光球或浓重光晕。
- 路面、车辆和障碍物仍以清晰的实体几何体呈现，保证信息可读性。

### 3.3 动效气质

- 起步、制动、转向和变道采用平滑插值，不出现瞬移。
- 路线在弯道处自然弯曲，并随决策重新规划。
- 转向灯以真实节奏闪烁，同时在车身灯具和状态区反馈。
- 镜头只做轻微跟随和转向补偿，不摇晃、不追求游戏速度感。
- 所有状态变化以 180-400ms 的克制动画衔接。

## 4. 功能范围

### 4.1 初始状态

- 页面加载后直接显示正在感知道路的中控可视化。
- 显示自车、道路、车道线、远处交通以及“激活 AP”主控件。
- 环境有轻微动态，但车辆不会自动开始完整驾驶流程。

### 4.2 激活 AP

- 用户点击一次激活控件。
- 状态依次经历：待命 -> 系统检查 -> AP 已激活 -> 自动驾驶。
- 蓝色规划路径由近到远点亮，速度平稳上升。
- 激活控件转为明确的蓝色 AP 状态指示，而不是继续作为大按钮存在。

### 4.3 道路生成

- 道路沿车辆前方持续生成并在后方回收，形成无限行驶效果。
- 随机组合直道、缓弯、较明显弯道和路宽变化。
- 支持 1-3 条同向车道，道路扩宽或收窄时必须有连续过渡。
- 车道线与规划路径遵循同一条道路曲线，避免视觉穿帮。
- 路侧可随机出现护栏、路灯、路牌、锥桶或施工区域。

### 4.4 交通与障碍物

- 周围车辆从可见范围外生成，具有不同速度和所在车道。
- 保持合理安全距离，避免车辆互相穿透或突然生成在自车附近。
- 障碍物包括慢车、静止车辆、锥桶组、施工封道和路面占用物。
- 每次事件应留出足够反应距离，让用户看清系统判断过程。
- 同屏对象数量动态控制，优先保证稳定帧率与视觉清晰度。

### 4.5 决策与自动变道

- 默认行为：沿规划路径巡航并保持车道中心。
- 前车较慢时先减速跟车，再评估左右相邻车道。
- 相邻车道安全且收益明显时，发起自动变道。
- 变道状态：评估 -> 开启转向灯 -> 等待安全窗口 -> 横向移动 -> 居中 -> 关闭转向灯。
- 若安全窗口消失，取消变道并关闭转向灯，不强行插入。
- 遇到封闭车道或障碍物时优先变道；无法变道时平稳刹停。
- 转弯与变道采用不同轨迹曲率，视觉上应易于区分。

### 4.6 车机信息

- 当前速度与限速。
- P/R/N/D 挡位中的当前状态。
- AP 待命、检查、激活、变道、受阻等状态。
- 简短决策提示，例如“正在等待安全变道时机”。
- 下一导航动作及距离，例如“前方 180 m 左转”。
- 不展示开发调试数据、FPS 或复杂参数面板。

## 5. 驾驶状态机

```text
待命
  -> 系统检查
  -> 自动巡航
      -> 跟车
      -> 道路转弯
      -> 变道评估
          -> 转向灯开启
          -> 等待安全窗口
          -> 执行变道
          -> 车道居中
      -> 障碍避让
      -> 无安全路径时刹停
```

任一临时行为完成后回到自动巡航。路径规划、车辆控制和视觉表现分别管理，避免随机场景直接操纵动画导致逻辑混乱。

## 6. 技术建议

- 使用 Three.js 构建全屏 WebGL 3D 场景。
- 使用 React 或原生模块管理车机 UI 与驾驶状态；若项目追求最小体积，可采用 Vite + TypeScript + Three.js。
- 路径使用 Catmull-Rom 曲线或等价样条曲线生成，车道线和车辆轨迹从同一中心线派生。
- 蓝色导航带使用带状几何体、渐变纹理与轻量 GPU 粒子组合实现。
- 交通对象采用对象池复用，避免持续创建和销毁模型。
- 使用确定性随机种子，既能持续变化，也便于复现问题。
- 对高 DPI 屏幕限制像素比，并为移动设备降低阴影、粒子和模型细节。
- 音效默认克制，包含接近官方听感的清脆、短促 AP 激活提示音和转向灯轻响，并提供静音入口。不得从非授权来源抓取官方音频；默认使用合成近似音色，若用户提供具有使用权限的官方音频文件，则直接替换。

## 7. 非目标

- 不连接真实车辆，也不宣称具备真实自动驾驶能力。
- 不使用 Tesla Logo、官方车型资产、字体或直接提取的原版 UI 资源；允许在整体构图、视觉层级与交互节奏上高度接近 FSD，使体验明确可辨。
- 不制作驾驶游戏，不加入积分、关卡、碰撞奖励或夸张速度效果。
- 不使用场景选择按钮、设置抽屉或大面积说明文字打断沉浸感。
- 第一版不实现地图导航、真实城市数据、账号系统或后端服务。

## 8. 验收标准

- 页面打开后 3 秒内出现完整且非空白的 3D 场景。
- 用户只需一次点击即可激活 AP，状态反馈明确。
- 蓝色路径能随直道、弯道和变道连续变化，无明显断裂或穿出道路。
- 至少支持直行、左右弯、道路变宽/变窄、慢车、静态障碍和施工封道。
- 自动变道全程符合“先打灯、再移动、完成后关灯”的顺序。
- 其他车辆与障碍物不会突然出现在自车近距离范围内。
- 车辆加减速、转弯和变道无瞬移或明显抖动。
- 桌面主流浏览器保持流畅；目标为普通设备 50-60 FPS，移动设备不低于 30 FPS。
- 1366x768、1440x900、1920x1080 与常见手机横屏下文字不重叠、控件不溢出。
- 界面中明确标注“视觉模拟演示”，避免被误认为真实驾驶系统。

## 10. 已确认的设计决定

1. 整体必须明显像 FSD，包括构图、视角、道路表达、蓝色路径与反馈节奏；不使用 Tesla 商标，也不逐像素复制官方界面。
2. 粒子只用于路径流动、激活扫描和感知反馈，不把整个道路粒子化。
3. 采用 FSD 常见的第三人称后上方视角，并作为主要且默认的驾驶视角。
4. 提供 AP 激活与转向灯声音。默认合成接近官方听感的音色；如用户提供具有使用权限的官方音频文件，则可替换为原声。
5. 自车采用 FSD 式中性灰色简化 3D 车体，不引入写实精细车型模型。
